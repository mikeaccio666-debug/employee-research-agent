## 1. 产品一页纸（给设计师的背景）

- **是什么**：一个会"采访"人的 AI。学生和它聊天，它把这个人画成一页独一无二、每句话都有出处的个人画像（`{domain}/@handle`）。Startup 用自然语言描述想要的人，agent 找到并解释为什么推荐，双方通过聊天和 coffee chat 连接。还有可匿名发布的动态广场，以及 startup 定期办的线上活动。
- **给谁用**：北美的大学生和应届生（含国际学生）；早期 startup 的创始人和招聘负责人。
- **最重要的三个界面**：① 画像工作室（左对话、右实时画像）；② 个人画像页；③ 企业端的匹配结果（印样）。
- **语言**：界面英文为主，支持简体中文；所有关键页面都要验证中英文两种排版。
- **代号**：Portrait（暂定），品牌名待定，原型中可用 "Portrait" 作为字标占位。

## 2. 设计原则

1. **像杂志一样郑重，像聊天一样轻松。** 每个人都值得一篇专访级别的个人特写；但做出它只需要聊天。
2. **内容就是界面。** 人和作品是主角，界面框架尽量退后。
3. **证据看得见。** "有出处"是我们和其他平台最大的区别，要在视觉上被一眼认出来（脚注）。
4. **同一个系统，每人不同。** 用一套设计系统做出千人千面，而不是千人一面的模板。
5. **动效讲因果。** 动效只用来解释"什么变了、为什么变"，不做装饰。
6. **匿名也要体面。** 化名用户有好看的指纹和名字，而不是灰色的默认头像。

**气质关键词**：editorial、精确、温暖、自信、有一点叛逆。
**不要**：企业 SaaS 后台感、可爱卡通、霓虹赛博、满屏毛玻璃、"AI 魔法"闪光感。

## 3. 视觉方向："活体杂志"与"编辑的红笔"

**核心隐喻**：agent 是采访你的记者；画像工作室是编辑部；个人画像页是刊出的人物特写；startup 看候选人像摄影师看印样（contact sheet），用红色油性笔圈出想聊的人。

**贯穿全站的视觉母题**

| 母题 | 用在哪里 |
|---|---|
| 大号的展示字体 | 画像页开场、落地页、活动海报 |
| 细线（hairline）与编辑网格 | 区块分隔、目录、数据表，代替卡片和阴影 |
| 区块编号（§01、§02）与页眉页脚 | 画像页、Brief 文档、公司页 |
| 证据脚注（上标 ¹ ² ³） | 画像中的每条事实；悬停弹出出处 |
| 编辑的红笔（唯一的平台强调色） | 选中、修改高亮、圈选候选人、待确认标记 |
| 画像指纹（Signature Glyph） | 头像、页面签名、分享卡片、网站图标、化名身份 |
| 页边批注（marginalia） | agent 的修改记录、匿名体检提醒，代替弹窗和 toast |

### 3.1 字体（候选，最终由 `/impeccable typeset` 和实测决定）

| 用途 | 拉丁字体候选 | 中文字体候选 | 说明 |
|---|---|---|---|
| 展示 / 标题 | **Fraunces**（可变：opsz、wght、SOFT、WONK）；备选 Instrument Serif | 思源宋体 Noto Serif SC（Heavy/Black）；前卫备选：得意黑 Smiley Sans | Fraunces 的可变轴可以给每个人不同的字形性格（写入 Page Spec 的 `typeAxes`） |
| 正文 / 界面 | **Instrument Sans**（可变：wdth、wght）；备选 Schibsted Grotesk | 思源黑体 Noto Sans SC | 不用 Inter、Arial、系统默认字体 |
| 元信息 / 数据 | **IBM Plex Mono**；备选 JetBrains Mono | 跟随正文字体 | 时间、编号、标签、状态行 |

以上均为开源授权（OFL）。

**中英混排规则**

- 中文正文行高 1.75–1.8，英文正文 1.55–1.6。
- 不对中文加字距；不用斜体表现中文强调（中文没有真正的斜体），改用字重或红笔下划线。
- 中英文之间留出间距（支持的浏览器用 `text-autospace`）；行首行尾标点挤压（`text-spacing-trim`）。
- 中文字体按 `unicode-range` 分片加载，首屏只加载用到的字。
- 阅读宽度：英文 60–72 字符，中文 32–38 字。

### 3.2 颜色（OKLCH 设计令牌，数值为起点，需实测对比度）

| 令牌 | 亮色"纸张" | 暗色"暗房" | 用途 |
|---|---|---|---|
| `--paper` | `oklch(0.975 0.008 85)` | `oklch(0.18 0.012 265)` | 页面底色（暖白，不是纯白） |
| `--paper-2` | `oklch(0.955 0.010 85)` | `oklch(0.22 0.012 265)` | 次级面（输入区、侧栏） |
| `--ink` | `oklch(0.22 0.020 265)` | `oklch(0.94 0.010 85)` | 主文字（带色调的近黑，不是纯黑） |
| `--ink-2` | `oklch(0.42 0.020 265)` | `oklch(0.78 0.012 85)` | 次要文字 |
| `--ink-3` | `oklch(0.52 0.015 265)` | `oklch(0.66 0.012 85)` | 元信息（需保证 ≥ 4.5:1） |
| `--rule` | `oklch(0.86 0.010 85)` | `oklch(0.30 0.012 265)` | 装饰性细线 |
| `--rule-strong` | `oklch(0.62 0.010 85)` | `oklch(0.50 0.012 265)` | 输入框等控件边界（≥ 3:1） |
| `--pen` | `oklch(0.60 0.20 32)` | `oklch(0.70 0.17 35)` | 编辑红笔：圈选、标记、大号文字 |
| `--pen-ink` | `oklch(0.52 0.19 30)` | `oklch(0.76 0.14 35)` | 红笔色的小号文字和链接（≥ 4.5:1） |
| `--pen-wash` | `oklch(0.60 0.20 32 / 0.14)` | `oklch(0.70 0.17 35 / 0.18)` | 修改高亮的底色 |

- **个人强调色**：每份画像有自己的强调色。agent 只选色相，明度和彩度由系统按亮暗主题计算并自动校验对比度。平台红笔色用于界面操作，个人强调色只用于画像内容本身，两者不混用。
- 禁止：紫蓝渐变、霓虹发光、灰字压在彩色底上、纯黑和纯灰。

### 3.3 版式与空间

- 12 栏编辑网格，桌面端栏间距 24px，内容最宽 1440px；鼓励不对称布局。
- 间距基于 4px：4、8、12、16、24、32、48、64、96、128、192。
- 字号（流式）：展示超大 `clamp(3.5rem, 2rem + 7vw, 10rem)`，行高 0.92；展示 `clamp(2.5rem, 1.6rem + 4vw, 5.5rem)`；H1 `clamp(2rem, 1.5rem + 2vw, 3rem)`；正文 17px；元信息 13px 等宽。
- 圆角：0–2px 为主（编辑式的锋利感）；只有标签可用全圆角。
- 层级：用细线和纸张色阶区分，几乎不用阴影；只有浮层使用一层柔和阴影。
- **不要**卡片套卡片，不要什么都装进带阴影的卡片。

### 3.4 动效

| 令牌 | 值 |
|---|---|
| `--ease-out` | `cubic-bezier(0.2, 0, 0, 1)` |
| `--ease-in-out` | `cubic-bezier(0.6, 0, 0.2, 1)` |
| 时长 | 120ms 微交互 · 200ms 小 · 320ms 中 · 600ms 揭幕 · 1200ms 指纹绘制 |

| 动效 | 描述 |
|---|---|
| 排版入场 | 新区块逐行淡入并上移 8px，像铅字被一行行排上去 |
| 修改高亮 | 红笔"马克笔"从左到右扫过被改动的文字（400ms），2 秒内淡出 |
| 诞生时刻 | 对话栏从居中滑到左侧（FLIP，600ms），右侧画像逐段排版，指纹被一笔笔"画"出来 |
| 指纹变形 | 画像更新时，指纹参数插值平滑过渡 |
| 圈选 | 候选人被一笔手绘的红圈圈住（描边动画 300ms） |

禁止弹跳、弹性缓动。所有动效在 `prefers-reduced-motion` 下降级为即时切换 + 静态高亮。

### 3.5 图形与图像

- **画像指纹**：生成式 SVG，3–7 笔，强调色加墨色；16px 到 480px 都可辨认；化名指纹用独立随机种子（不能和实名指纹关联）。请设计 6–8 个不同人物的指纹样例，展示多样性。
- **图标**：能用文字就不用图标；必须用时采用 1.5px 描边的线性图标。**不要**每个标题上方都放一个圆角方块图标。
- **图像**：不用办公室里微笑人群的图库照片。画面来自用户自己的作品截图、指纹、字体排版。
- 不用 ✨ 之类的"AI 魔法"符号来表示 AI。

## 4. 画像页主题预设（MVP 三套）

同一套系统，三种气质；再乘以个人强调色、字形可变轴、疏密、区块顺序和变体、指纹，保证每一页都不同。

| 预设 | 适合 | 特征 |
|---|---|---|
| **Editorial**（默认） | 所有人 | Fraunces 大标题、不对称网格、引用本人原话的大号引文、区块编号、留白充足 |
| **Instrument** | 工程师、研究者 | 等宽字体为主，网格线可见，经历像仪表或数据表一样排列，坐标式标注；适合暗色 |
| **Gallery** | 设计师、创作者 | 作品出血大图、文字极少、大号图注、可横向浏览的作品墙（有无障碍控件） |

## 5. 核心交互模式

1. **对话与画布联动**：悬停对话里的一条"修改回执"，右侧对应区块高亮；反过来，悬停画布上的区块，左侧显示它来自哪几句对话。
2. **点选即编辑**：点击画布上的区块，出现红笔方括号；对话输入框出现上下文标签"Editing: Projects › Campus marketplace"，用户直接说要怎么改。
3. **证据脚注**：每条事实带上标脚注；点开显示原话或原文摘录、来源（对话、简历第几页、链接）、时间。依据类型用标记区分：实心点＝已展示，空心点＝自述，虚线点＝推断待确认，对勾＝已验证。
4. **待确认**：推断内容带虚线下划线，行内有"对 / 改"两个操作；发布按钮旁显示"4 things to confirm"。
5. **页边批注**：agent 的每次修改在页边留一条小字批注（"edited just now · undo"），代替 toast。
6. **视角切换**：Public / Anonymous / As a startup sees it，三种视角一键切换，帮助用户理解隐私设置。
7. **匿名体检**：以化名发帖前，风险提示以红笔批注的形式出现在对应文字或图片旁边。
8. **印样圈选**：企业端用红圈圈选候选人，用删除线划掉并选择原因；支持键盘（J/K 移动，C 圈选，X 划掉，Enter 打开）。
9. **时间选择**：coffee chat 的时间网格以字体排版呈现，同时显示双方时区。
10. **命令栏**（⌘K）：给熟练用户的快速跳转和操作。

## 7. 屏幕清单（P0）

按建议的制作顺序排列。每个屏幕都需要：桌面（1440）+ 移动（390）两个尺寸；亮色为主，标注了"暗色"的需要额外出暗色版；标注了"中文"的需要额外出中文版。

### S1 画像工作室 Studio（最重要，桌面 + 移动 + 中文）

- **目的**：用户一边和 agent 聊，一边看自己的画像被不断丰富。
- **桌面布局**：顶栏横跨全宽：左侧字标；中间是链接胶囊 `{domain}/@lin` 和可见性状态（"Anonymous · discoverable"）；右侧是视角切换、主题、历史、**Publish**（红笔色主按钮）。下方左右分栏：左侧对话栏约 38%（最小 380px，可拖动分隔线），右侧画布展示真实比例的画像页。
- **对话栏**：做成**采访实录**而不是聊天气泡：agent 的话用无衬线粗体，用户的话用衬线正文，左侧是细小的说话人标记；工具调用以"修改回执"出现（"✎ Added to Projects — Campus marketplace"），悬停时联动画布；底部输入区上方是 2–3 个建议标签（"Add a demo link"），输入区内可附件、可显示上下文标签。
- **画布**：被修改的区块出现红笔高亮扫过；页边批注；被选中的区块有红笔方括号；待确认内容有虚线下划线。
- **状态**：首次加载、agent 正在思考（等宽状态行，如 "Reading résumé · page 2 of 2"）、流式输出中、工具执行中、出错（输入内容不丢）、离线。
- **移动端**：对话全屏；底部有一条"画像预览条"（缩略图 + 最近一次修改"Projects updated"），点开后画像全屏，右下角浮动"Talk"按钮返回对话；在画像上点选区块会跳回对话并带上上下文标签。

### S2 个人画像页（三套主题 × 桌面 + 移动；Editorial 出暗色和中文版）

- **目的**：门面。让看到的人 10 秒内记住这个人哪里不一样，30 秒内找到证据。
- **区块**：开场（名字或化名、一句话标题、当前状态、指纹）→ §01 签名段 → §02 三项超能力（带脚注）→ §03 经历（时间线）→ §04 作品 → §05 做事方式 → §06 在找什么 → §07 最近动态 → §08 可以问我 → 页脚 "Drawn with Portrait · Draw yours"。
- **行动按钮**：Book a coffee chat（主）、Message、Save。
- **分享卡片（OG 图）**：1200×630，指纹 + 名字 + 一句话标题，三套主题各一张。
- 用同一个虚构人物（Lin，CS 大三）的内容做三套主题，直观展示"同一个人、三种气质"；再用另外两个虚构人物（设计师 Maya、转专业的 Alex）做 Editorial 版，展示"同一主题、不同的人"。

### S3 落地页（桌面 + 移动 + 中文）

- **首屏**：整屏只有一句超大的话 **"I'm looking for work."**，其中 "work" 是红笔色、可点击的词，点击后通过字形可变轴的过渡变成 "people"（语义上是一个两项的单选，键盘可操作）。下方是对话输入框，占位文案随之变化；输入框支持拖入简历。输入框下方一行小字："No sign-up needed. You'll see your portrait in about five minutes."
- **往下滚**：一排示例画像的"印样"（指纹 + 一句话标题）；三步说明（Talk → See your portrait → Get found）；面向 startup 的一段；近期活动；页脚。
- 切换到 "people" 后，首屏下方的内容换成面向 startup 的版本。

### S4 诞生时刻（分镜，5–6 帧，桌面 + 移动）

- 帧 1：全屏对话（居中一栏），agent 说"Your first draft is ready. Want to see it?"，下方按钮 "Show me"。
- 帧 2：对话栏开始向左滑。
- 帧 3：右侧画像逐段排版，指纹被画出。
- 帧 4：顶部打出链接 `{domain}/@lin`，旁边是 "Claim this link"。
- 帧 5：登录面板（Google / LinkedIn / GitHub / Email）。
- 帧 6：可见性设置（见 S15），默认选中 "Anonymous · discoverable"。

### S5 企业入口与 Brief 工作室（桌面）

- 与 S1 镜像：左侧对话，右侧是一份"岗位画像"文档（像一页规格说明书）：标题、这个岗位要完成什么、Must / Nice / Signals we love / Logistics 四个区块，每条必须项都附"why"。
- 右上角是实时人才池预览："124 match the basics · 18 strong"，旁边提示"放宽某一条会变成多少人"。
- 展示一次公平护栏：用户输入 "under 25 only"，agent 婉拒并给出替代建议，文档中不出现该条件。

### S6 印样：匹配结果（桌面 + 移动）

- **布局**：左侧是网格排列的候选人"帧"（桌面 3–4 列），每帧左上角是帧号（07A、08A……）；右侧是固定的 Brief 摘要栏。
- **每一帧**：指纹 + 化名或实名、一句话标题、3 条带脚注的推荐理由、每个必须项的满足情况（实心、半实心、空心三种小方块，悬停显示是哪一条）、对方可能感兴趣的程度、可入职时间。帧与帧之间用细线分隔，**不用带阴影的卡片**。
- **操作**：悬停出现"Circle / Strike"；被圈选的帧有手绘红圈；被划掉的帧有删除线并收起，可撤销。
- **顶部**：Brief 标题；All / Circled / Contacted 三个标签页；筛选。
- **状态**：计算中（先出检索结果，再逐帧补上理由）、没有强匹配时的空状态（给出放宽建议）。

### S7 候选人详情（企业视角，桌面）

- 中间是候选人的画像页（匿名版或实名版）；右侧是"Match notes"面板：每个必须项的判断和证据（点击后画像滚动到对应区块并高亮）、潜在顾虑、建议在 coffee chat 里问的问题。
- 面板底部是外联编辑器：agent 起草的附言（可编辑）、类型（Chat / Coffee chat）、剩余额度。
- 需要一张匿名版和一张接受连接后实名版的对比。

### S8 收件箱与 Coffee Chat（桌面 + 移动）

- 三栏：列表（Requests / Messages / Coffee chats 筛选）→ 对话 → 右侧上下文（对方的画像或公司摘要、已约的时间）。
- 连接请求视图：对方公司画像摘要、附言、关联岗位、Accept / Not now / Decline。
- 时间选择：对话中插入的卡片，打开后是字体排版的一周时间网格；同时显示双方时区；确认后显示"已加入日历"和会议链接。

### S9 动态广场（桌面 + 移动 + 中文）

- 单栏信息流（最宽 680px），左侧窄导航，右侧是近期活动和推荐关注。
- 顶部发布框：身份切换"Posting as: quiet-otter ▾"（化名 / 实名 / 公司）；类型：文字、图片、链接、项目展示；匿名体检提醒以页边批注形式出现。
- 每条动态：身份行（指纹 + 化名或名字 + 等宽的上下文标签，如 "CS · Junior · Bay Area"）、内容、共鸣、评论、分享；企业成员看到的化名动态上多一个 "Invite to chat"。
- 项目展示类动态：大图 + 标题 + 链接 + 标签。

### S10 活动（桌面 + 移动）

- **活动列表**：做成"节目单"：左侧大号日期数字，右侧标题、主办公司、类型（AMA、宣讲、圆桌……）、本地时间、报名按钮；顶部按周切换，可筛选。
- **活动页**：海报式开场（由公司强调色和字体排版生成，或上传封面）、简介、议程、主持人、报名（含"把我的画像分享给主办方"开关，默认关闭）、会前问题区（可投票，可化名）、开始前 10 分钟出现的 "Join" 按钮。
- **主办方创建**：一句话让 agent 起草（"AMA next Thursday 6pm PT about our founding engineer role"），右侧实时预览活动页。

### S11 公司画像页（桌面 + 移动）

- 编辑式的公司特写：超大的使命句、事实侧栏（阶段、人数、技术栈、办公方式）、创始人的话、开放岗位、近期活动、Office Hours（可直接预约）、公司动态。

### S12 隐私与可见性设置（桌面 + 移动）

- 四个大选项（Public / Anonymous · discoverable / Link only / Hidden），新用户默认是 Anonymous · discoverable；每个选项写清楚"谁能看到什么"；右侧实时预览"startup 会看到的样子"。
- 敏感字段逐项设置：签证需求、薪资期望、联系方式。
- 数据导出、删除账号、化名管理。

### S13 价格与付费时刻

- 价格页：诚实、排版清晰的对比表；不使用"仅剩 2 个名额"之类的虚假稀缺。
- 付费时刻：企业额度用完时，在发送连接请求的位置出现说明和升级入口，而不是全屏拦截。

### S14 状态合集

- 空状态、加载（"排版中"的骨架线条，而不是通用的闪光骨架屏）、流式输出、错误、离线、404（例如 handle 不存在："This portrait hasn't been drawn yet. Draw yours?"）。

### S15 首次发布前的可见性选择（可与 S12 共用组件）

诞生时刻之后、第一次发布之前出现的一步：四个选项，默认选中 "Anonymous · discoverable"，每个选项用一句话说明谁能看到什么；用户可以一键确认，也可以改成其他模式。

### S16 邮件模板（P1，可后做）

连接请求、请求被接受、coffee chat 确认与提醒、活动提醒、新匹配摘要。

## 9. 文案语气

- **对求职者**：温暖、直接、好奇；鼓励但不吹捧；句子短。
- **对 startup**：利落、高效、诚实。
- **避免**：一串感叹号、"Oops!"、"Awesome!"、表情符号、"AI-powered"、"Unlock your potential" 这类空话；中文避免"亲"和过度口语化。
- 代词：界面提到用户时使用名字或 they/them，除非用户自己填写了代词。

| 场景 | English | 中文 |
|---|---|---|
| 落地页标题 | I'm looking for **work**. / I'm looking for **people**. | 我在找**工作**。/ 我在找**人**。 |
| 落地页输入框 | Tell me about yourself — or drop your résumé. | 介绍一下你自己，或者直接拖入简历。 |
| 落地页提示 | No sign-up needed. You'll see your portrait in about five minutes. | 不用注册，大约 5 分钟就能看到你的画像。 |
| 诞生时刻 | Here's your first draft. It's yours to shape. | 这是你的第一版画像，接下来由你来塑造。 |
| 认领链接 | Claim {domain}/@lin | 认领 {domain}/@lin |
| 待确认 | 4 things to confirm before you publish | 发布前还有 4 处待确认 |
| 匿名体检 | Heads up: the screenshot shows your school's logo. Posting as quiet-otter could reveal who you are. | 提醒：截图里有学校 logo，以化名发布可能会暴露你的身份。 |
| 公平护栏 | We don't filter by age. Want to describe the pace and responsibilities instead? | 我们不按年龄筛选。要不要改成描述这个岗位的节奏和职责？ |
| 印样标题 | 18 strong matches, each with reasons you can check. | 18 位强匹配，每一位都附有可查证的理由。 |
| 无强匹配 | No one meets all five must-haves yet. Making Rust a nice-to-have widens the pool to 86. | 还没有人同时满足 5 个必须项。把 Rust 改成加分项，人数会变成 86。 |
| 出错 | That didn't go through. Your message is safe — try again. | 没发出去。你写的内容还在，再试一次。 |
| 404 | This portrait hasn't been drawn yet. Draw yours? | 这幅画像还没有被画出来。要画你自己的吗？ |

## 10. 无障碍与响应式

- WCAG 2.2 AA：正文对比度 ≥ 4.5:1，大字和控件边界 ≥ 3:1；焦点清晰可见（红笔色焦点环）；触控目标 ≥ 44px。
- 流式输出：对话区使用 `aria-live="polite"`，按句子而不是按字播报；画布的修改用一条可读的文字说明播报（"Projects section updated"）。
- 句式切换词、圈选、时间网格等自定义控件都要有正确的语义角色和键盘操作。
- 断点：390（手机）、768（平板）、1280（笔记本）、1440+（桌面）。画像页移动端优先。
- 支持 `prefers-reduced-motion` 和 `prefers-color-scheme`。

## 11. 反模式清单（出现即返工）

**Impeccable 列出的常见"AI 味"**

- 过度使用的字体（Inter、Arial、系统默认字体）
- 紫到蓝的渐变；深色背景上的发光效果
- 卡片套卡片；什么都包进卡片
- 灰色文字压在彩色背景上
- 纯黑或纯灰（应带色调）
- 弹跳或弹性缓动
- 侧边色条边框（side-tab borders）
- 每个标题上方都放一个圆角方块图标

**本产品额外禁止**

- 千篇一律的聊天气泡（两边头像 + 跳动的三个点）
- 到处出现 ✨ 来表示 AI
- 给求职者看的 KPI 仪表盘卡片
- 图库照片
- "资料完整度 60%"这类游戏化进度条
- LinkedIn 蓝
- 简历模板式的技能条（★★★☆☆）。我们用证据，不用自评星级
- 付费页的暗黑模式（虚假倒计时、虚假稀缺）
- 庆祝时的彩带和表情符号

### 12.1 主提示词（先建设计系统）

```text

一句话：一个会采访人的 AI。学生和它聊天，它把这个人画成一页独一无二、每句话都有出处的个人画像；startup 描述想要的人，agent 找到并解释为什么推荐。
```

## 13. 用 Impeccable 做设计把关

[Impeccable](https://impeccable.style)（本文基于 v4.6）是给 AI 编程工具用的设计技能包：1 个技能、24 个命令，以及 59 条确定性的反模式检测规则（命令行可直接运行，不需要大模型）。

### 13.1 安装（在代码仓库里）

```bash
# 在仓库根目录
npx impeccable install          # 选择 Claude Code，作用域选 project
# 或在 Claude Code 里：/plugin marketplace add pbakaus/impeccable，然后在 /plugin 中安装
```

安装后：

- 运行 `/impeccable init`，生成 `PRODUCT.md`（受众、目的、使用场景、约束、语气、依据）。可以直接用 §13.4 的素材回答它的问题。
- 把 Impeccable README 中 `# impeccable-ignore-start` 到 `# impeccable-ignore-end` 的那段规则加进 `.gitignore`；`.impeccable/config.json`、`design.json`、`surfaces/*.md`、`critique/*.md` 要提交进仓库。
- Claude Code 会装上一个设计钩子：每次编辑 UI 文件都会自动运行检测，把问题反馈给 agent。
- 关于 `buildPath`：Impeccable 可以先出效果图再写代码（`comp`），也可以直接写代码（`code`）。我们的效果图由 Claude Design 负责，所以建议设为 `code`，把 Claude Design 的定稿作为参照。

### 13.2 每个阶段用哪些命令

| 阶段 | 命令 | 用来做什么 |
|---|---|---|
| 开始一个新界面之前 | `/impeccable shape <界面>` | 写代码前规划 UX/UI，附上 Claude Design 定稿作为参照 |
| 设计系统落地后 | `/impeccable document` | 根据代码生成根目录的 `DESIGN.md` |
| | `/impeccable extract` | 把可复用的组件和令牌抽进设计系统 |
| 实现中（按需） | `/impeccable typeset` | 中英文字体搭配、层级、字号 |
| | `/impeccable layout` | 布局、间距、节奏 |
| | `/impeccable colorize` | 个人强调色的生成与使用 |
| | `/impeccable animate` | 修改高亮、诞生时刻、圈选等动效 |
| | `/impeccable onboard` | 落地页 → 诞生时刻 → 发布的首次体验 |
| | `/impeccable clarify` | 界面文案 |
| | `/impeccable adapt` | 工作室和画像页的移动端适配 |
| | `/impeccable delight` / `overdrive` | 诞生时刻、指纹绘制这类"惊艳时刻"（克制使用） |
| | `/impeccable bolder` / `quieter` / `distill` | 太平淡就加强，太吵就收敛，太复杂就做减法 |
| 每个界面完成时（把关） | `/impeccable critique <界面>` | UX 评审：层级、清晰度、情感共鸣 |
| | `/impeccable audit <界面>` | 技术质量：无障碍、性能、响应式 |
| | `/impeccable harden <界面>` | 边界情况：超长名字、超长中文、0/1/多条数据、错误、国际化 |
| | `/impeccable polish <界面>` | 上线前的最后一遍：对齐、间距、细节、与设计系统一致 |
| 视觉迭代 | `/impeccable live` / `generate` | 在浏览器里对某个元素生成变体并挑选 |

常用的命令可以用 `/impeccable pin audit` 固定成 `/audit` 这样的快捷命令。

### 13.3 自动检测与验收

**CI 里的检测**（GitHub Actions 示例）：

```yaml
- name: Impeccable anti-pattern scan
  run: npx impeccable detect --json apps/web/src > impeccable-report.json
  # 退出码：0 = 无主要问题；2 = 发现主要问题（让 CI 失败）；1 = 有目标无法扫描
```

确有理由的例外，用 `npx impeccable ignores add-value <规则> <值> --reason "<理由>"` 记录，不要静默关闭规则。

**每个界面的验收清单**

- [ ] `npx impeccable detect`：0 个主要问题（或有记录的例外）
- [ ] `/impeccable critique`：P0/P1 级问题已修复
- [ ] `/impeccable audit`：无障碍零严重问题；对比度、键盘、焦点、触控目标达标
- [ ] `/impeccable harden`：超长内容、空数据、错误、慢网络、中英文都检查过
- [ ] 在 390 / 768 / 1280 / 1440 宽度下人工检查
- [ ] 亮色、暗色、`prefers-reduced-motion` 都检查过
- [ ] 公开画像页：移动端 LCP < 2.0s，CLS < 0.05，首屏 JS ≤ 100KB（gzip）
- [ ] `/impeccable polish` 完成

### 13.4 `/impeccable init` 素材（PRODUCT.md）

- **受众**：北美的大学生和应届生（含国际学生，很多人英文表达不自信）；早期 startup 的创始人和招聘负责人（时间极少）。
- **目的**：让求职者通过聊天得到一页独一无二、有证据的个人画像并被对的人发现；让 startup 快速找到、读懂并联系上合适的人。
- **使用场景**：学生多在手机上打开别人分享的画像链接，在笔记本上建档；创始人在笔记本上一次处理一批候选人，习惯键盘操作。
- **约束**：英文为主、中文支持；WCAG 2.2 AA；公开页移动端性能预算；匿名模式下绝不泄露身份；所有事实性内容必须带出处。
- **语气**：对求职者温暖、直接、好奇；对 startup 利落、诚实；不吹捧、不用 AI 套话。
- **依据**：用户访谈与设计伙伴反馈（待补充）；PRD 第 10 节的指标目标。
